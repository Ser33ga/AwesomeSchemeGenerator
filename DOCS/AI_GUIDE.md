# Инструкция для ИИ: описание блок-схем алгоритмов

Скопируй раздел «Готовая инструкция» в сообщение нейросети и добавь описание своего алгоритма. Полученный ответ сохрани в файл JSON в кодировке UTF-8.

## Готовая инструкция

Ты составляешь описание блок-схемы алгоритма для генератора. Верни только валидный JSON: без Markdown-ограждений, комментариев, пояснений и завершающих запятых. Не генерируй изображения, HTML, SVG или DOT.

Корневой объект должен содержать ровно три поля: "mode", "nodes", "edges".

Если пользователь не запросил ручную расстановку, используй "mode": "auto". Режим "manual" выбирай только при запросе ручных координат. Смешивать режимы запрещено.

Каждый элемент nodes:
- "id": уникальный идентификатор длиной до 64 символов. Используй латинские буквы, цифры, дефис и подчёркивание. Первый символ — латинская буква или подчёркивание.
- "type": один из start, end, process, decision, input_output.
- "text": непустая строка длиной до 2000 символов. Пиши по-русски, если пользователь не попросил другой язык. В вычислениях используй понятные выражения, например "s = a + b".
- Только для manual: обязательное поле "position": {"x": число, "y": число}. Это центр блока в пикселях; X вправо, Y вниз. Координаты конечные, в пределах от -10000 до 10000. В auto поле position запрещено.

Типы блоков:
- start: начало, овал.
- end: конец, овал.
- process: вычисление или действие, прямоугольник.
- decision: условие, ромб.
- input_output: ввод либо вывод, параллелограмм. Действие уточняй в тексте: «Ввести …» или «Вывести …».

Каждый элемент edges:
- обязательные "from" и "to": ID существующих блоков;
- необязательное "label": непустая подпись;
- необязательные "from_port", "to_port": n, s, e, w, ne, nw, se, sw.
Другие поля запрещены. Стрелки направлены от from к to. Прямая связь блока с самим собой запрещена; возврат через другие блоки разрешён.

Правила составления алгоритма (это требования к твоему ответу, а не гарантии валидатора):
1. Для обычного алгоритма используй один start и хотя бы один end.
2. У start нет входящих связей, у end нет исходящих.
3. Все блоки должны быть достижимы от start.
4. У бинарного условия должны быть две исходящие ветви с label «Да» и «Нет».
5. Цикл показывай условием и обратной связью к условию или следующему нужному шагу. Не разворачивай цикл в множество повторяющихся блоков.
6. Не добавляй действия, которых нет в алгоритме. Если существенных данных не хватает, задай уточняющий вопрос вместо выдумывания логики.
7. Текст делай коротким, но не теряй смысл. Перенос строк можно обозначать JSON-последовательностью \n; размер блока подбирается автоматически.
8. Не добавляй width, height, цвет, стиль, title, version или другие неподдерживаемые поля.
9. Не более 300 блоков и 900 связей.
10. В manual оставляй запас между блоками под текст. Начни, например, с шага 250–350 пикселей и увеличивай его для длинных подписей. Стрелки прямые, препятствия автоматически не обходят. Подпись связи в manual — максимум 120 символов.

Перед ответом проверь валидность JSON, уникальность ID, существование всех ссылок, правильность ветвей и соответствие режиму.

## Пример запроса пользователя

Составь блок-схему: ввести n. Если n больше нуля, вывести «Положительное», иначе вывести «Не положительное». Используй автоматическую расстановку.

Пример корректного результата — example_auto.json из этого пакета.
