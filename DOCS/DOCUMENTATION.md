# Документация генератора блок-схем

Документ описывает ранее выданную версию flowchart.py. Этот пакет содержит документацию и примеры, а не новую версию программы.

## Что делает программа

Читает JSON в UTF-8, проверяет структуру и создаёт два файла: PNG и SVG. Браузер и интернет при рендеринге не используются. Для auto применяется Graphviz dot. Для manual используется отдельный SVG-рендерер и конвертация SVG в PNG через CairoSVG.

## Установка

Нужен Python 3.10 или новее.

Для auto установи системную программу Graphviz и добавь каталог с dot в PATH. Пакет Python graphviz отдельно не требуется: скрипт запускает dot через subprocess.

Проверка:
```bash
python --version
dot -V
```

Для manual нужны дополнительные зависимости:
```bash
python -m pip install pillow cairosvg
```
Также необходима системная библиотека Cairo. В текущем коде путь к шрифту жёстко задан: `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`. На Windows или при другом расположении шрифта нужно изменить переменную font_path в функции render_manual на существующий TTF-шрифт с поддержкой кириллицы. Одного pip install на некоторых системах недостаточно. Автоматический режим не зависит от Pillow и CairoSVG.

## Запуск

Открой терминал в папке со скриптом и JSON.
```bash
python flowchart.py example_auto.json
python flowchart.py example_manual.json
python flowchart.py my_scheme.json -o result
python flowchart.py --help
```

Без -o выходные файлы получают имя входного файла с расширениями .png и .svg. Параметр -o задаёт базовое имя, не каталог. Например, -o results/scheme создаст results/scheme.png и results/scheme.svg; родительский каталог создаётся автоматически. Не добавляй расширение к базовому имени.

Существующие файлы с такими именами перезаписываются. При ошибке программа выводит сообщение и завершает работу с кодом 1. Рендеринг auto имеет тайм-аут 30 секунд на каждый формат. Вывод двух форматов не транзакционный: при сбое второго может остаться первый.

## Формат входного файла

Корень содержит строго mode, nodes, edges.

| Поле | Тип | Значение |
|---|---|---|
| mode | строка | auto или manual |
| nodes | массив | От 1 до 300 блоков |
| edges | массив | От 0 до 900 связей |

### Блоки

Обязательные поля: id, type, text. В manual также обязательно position. Других полей быть не должно.

| type | Значение | Форма |
|---|---|---|
| start | Начало | Овал |
| end | Конец | Овал |
| process | Вычисление или действие | Прямоугольник |
| decision | Условие | Ромб |
| input_output | Ввод или вывод | Параллелограмм |

id уникален, не длиннее 64 символов, соответствует `[A-Za-z_][A-Za-z_0-9-]*`. text — непустая строка, не более 2000 символов.

Пример блока auto:
```json
{"id": "calc", "type": "process", "text": "s = a + b"}
```

Пример блока manual:
```json
{"id": "calc", "type": "process", "text": "s = a + b", "position": {"x": 200, "y": 300}}
```

position содержит ровно x и y — конечные числа от -10000 до 10000, не логические значения. Координаты обозначают центр блока, X растёт вправо, Y вниз. В auto координаты запрещены. Нулевой или отрицательный X/Y допустим: SVG автоматически получает нужную область просмотра.

Размеры и переносы текста рассчитывает программа. Лимит переноса — примерно 24 символа для подписи блока; ручной рендерер дополнительно измеряет ширину текста шрифтом. Ручные размеры не поддерживаются. Не считай шаг между центрами гарантией отсутствия перекрытий: размеры зависят от текста.

### Связи

Обязательны from и to; необязательны label, from_port, to_port. Других полей нет.
```json
{"from": "check", "to": "positive", "label": "Да", "from_port": "s", "to_port": "n"}
```

from и to должны ссылаться на существующие блоки. Связь блока с самим собой запрещена. Связи назад к другим блокам разрешены и позволяют описывать циклы.

Порты: n — сверху, s — снизу, e — справа, w — слева, ne/nw/se/sw — диагональные направления. Без портов выбираются точки подключения автоматически. В manual диагональные порты приблизительны для некоторых фигур.

label — непустая строка до 2000 символов; для manual дополнительно максимум 120. Для бинарных условий используй «Да» и «Нет».

## Режимы и ограничения

### auto

Graphviz размещает блоки преимущественно сверху вниз и рассчитывает стрелки. Координаты из JSON не принимаются. Сложные циклы и густые схемы могут получаться неидеальными. Точные координаты и размеры экспортированной схемы не гарантируются.

### manual

Все блоки должны иметь координаты; смешанный режим отсутствует. Стрелки идут прямо от точки подключения одного блока к другому, без обхода промежуточных блоков. Пересечения, перекрытия блоков и подписи стрелок нужно учитывать при расстановке. Прямоугольники здесь имеют небольшое скругление углов.

Лимиты ручного изображения: не более 16000 пикселей по каждой стороне и не более 40000000 пикселей площади. Расстояния, слишком большие для этих лимитов, приводят к ошибке. Это ограничение текущего рендерера, а не JSON-формата.

## Что проверяет валидатор

Проверяет обязательные и лишние поля, режим, типы блоков, формат и уникальность ID, наличие целей связей, допустимость портов, длину текста и корректность координат.

Не проверяет смысл вычислений, количество стартов и концов, достижимость блоков, обязательность двух ветвей условия, наличие их подписей или завершение алгоритма. Указанные правила нужно требовать от ИИ и проверять отдельно.

## Типичные ошибки

- `dot` не найден: установи Graphviz, проверь PATH и переоткрой терминал.
- JSON не разбирается: убери Markdown-обёртку, комментарии и лишние запятые; ключи и строки должны быть в двойных кавычках.
- Неизвестный ID в связи: from/to должны точно совпадать с id блока.
- Ошибка состава полей: не добавляй координаты в auto; добавь position каждому блоку manual.
- Font not found: исправь font_path на существующий шрифт.
- Ошибка Cairo: установи системную Cairo; одних пакетов Python может быть недостаточно.
- Блоки перекрываются в manual: увеличь расстояния между центрами или сократи текст.

## Работа с нейросетью

Используй AI_GUIDE.md как инструкцию, добавив текст алгоритма. Сохраняй ответ в UTF-8 без Markdown-ограждений, затем запускай скрипт. Для проверки формата вместе с инструкцией можно приложить example_auto.json или example_manual.json.
